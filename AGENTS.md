# Auctorio Codex workflow

- Use PowerShell and explicit RTK commands where supported. Keep full errors and logs available locally. Use Context Mode for large outputs and Serena for focused symbol relationships when available.
- For code work, query `graphify-out/graph.json` with Graphify before broad source reads. Verify results in source. Check Git changes for staleness. Initialize or update only when needed, using local deterministic extraction or OpenAI inference. Exclude secrets, dependencies and generated files. If the index is unavailable, report it and use bounded searches.
- Apply Ponytail full to implementation and debugging. Reuse existing code and make the smallest complete change. Apply the Caveman skill to chat and worker summaries from session start. Keep exact paths, commands, errors and evidence references.
- The orchestrator uses OpenAI GPT-6.2 Sol medium and owns planning, integration and acceptance. Use native named agents with their declared models. Terra medium implements, debugs and reviews. Luna low explores and documents. Treat unavailable roles or models as blocked. Check effective routing and never accept a substitute or use another inference provider.
- Run mechanical work and trivial edits directly. Delegate standard coding to `implementer` when the scope justifies the handoff. Split complex work only into independent scopes, up to two workers. Require independent `reviewer` evidence for high-risk changes. Use `debugger` for failures needing interpretation. Workers never spawn agents.
- Send only the goal, relevant paths or graph references, constraints, acceptance criteria and evidence expected. Avoid full-history forks. Assign one owner per file and integrate centrally.
- Run relevant deterministic checks locally. After a failure, allow up to two focused correction attempts, each followed by verification. Then return control to the orchestrator. Verify integrated results before reporting success.
- Use native session telemetry for available model, effort and token counts. Record duration, worker count, retries and test exit status when reporting evidence. Label unavailable metrics and keep subscription usage separate from API estimates.
